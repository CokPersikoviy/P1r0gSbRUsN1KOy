## Что даёт мод

FrogHelper собирает важную игровую информацию в одном месте и показывает её прямо во время игры:

- таймеры боссов, способностей, посохов, зелий, продавцов и майнеров, а также состояния рун и питомцев;
- прогресс уровня и комбо;
- удобные HUD-виджеты с редактором расположения и режимом UnClutter;
- переключение наборов рун по настраиваемым хоткеям;
- карта данжа/осады, рецепты, fishing-информация, pop-up уведомления;
- улучшения чата и внутриигровой обмен данными между игроками с FrogHelper;
- Quick Access для быстрых команд по удержанию одной клавиши;
- ESP и подсветка полезных объектов;
- Discord Rich Presence с игровым контекстом;
- локальные уведомления о важных событиях.

## Быстрый старт

После входа в игру полезно знать несколько основных действий:

| Действие | По умолчанию |
| --- | --- |
| Включить режим редактирования HUD | `H` |
| Открыть меню настроек | `O` |
| Открыть Quick Access | удерживать `R` |
| Включить / выключить авто-кликер | `K` |

Дополнительно:

| Действие | По умолчанию |
| --- | --- |
| `clanhide` | `Z` |
| `runesbag` | `X` |

## Основные хоткеи

### `H` — Editing Mode

Открывает режим редактирования HUD. В нём можно:

- двигать виджеты;
- менять масштаб;
- привязывать их к якорям экрана;
- сцеплять виджеты между собой;
- таскать связанные группы;
- добавлять виджеты из боковой панели и удалять их из основной раскладки.

### `O` — Settings Menu

Открывает внутреннее меню настроек FrogHelper. Через него настраиваются:

- виджеты;
- Quick Access;
- чат;
- pop-ups;
- fishing;
- render и highlight-опции;
- Discord RPC;
- темы;
- clicker и другие утилиты.

### `R` — Quick Access

Работает по принципу удержания:

1. зажимаете `R`;
2. наводитесь на нужную команду;
3. отпускаете клавишу;
4. команда выполняется автоматически.

### `K` — Clicker

Переключает авто-кликер. Он может:

- бить как обычная атака;
- использовать предмет вместо атаки;
- работать с заданным CPS.

### `Z` — Clan Hide

Отправляет команду `clanhide`.

### `X` — Runes Bag

Отправляет команду `runesbag`.

### `1`–`7` — выбор набора рун

При открытом окне рун-мешка эти клавиши переключают активный набор рун (1–7). Также работают стрелки `←` / `→` для перебора наборов.

Клавиши переназначаемые: `Options → Controls → категория FrogHelper → Rune Set 1…7`. По умолчанию — цифры `1`–`7`. Они срабатывают только внутри окна рун-мешка, поэтому не конфликтуют с выбором слотов хотбара в обычной игре.

## Редактор HUD

Редактор HUD нужен для полной подгонки интерфейса под себя.

У новых пользователей основная раскладка пустая. При обновлении текущие видимые виджеты автоматически переносятся с сохранением позиций, масштаба и привязок. Ранее отключённые или свёрнутые виджеты остаются в библиотеке для повторного добавления.

Боковая панель содержит все доступные виджеты, поиск и прокрутку. Нажмите `+` или строку отсутствующего виджета, чтобы добавить его. Панель можно свернуть стрелкой в заголовке, чтобы добраться до виджетов у левого края экрана.

Переключатель рядом с названием раскладки сортирует список: `A-Z` — по алфавиту, `ON` — сначала добавленные в выбранную раскладку, `OFF` — сначала остальные. Внутри групп сохраняется алфавитный порядок. ЛКМ переключает вперёд, ПКМ — назад; выбранный режим сохраняется.

Виджет **Roulette Timer** автоматически запоминает таймер голограммы «До следующего прокрута» при приближении к рулетке на DW. Время окончания сохраняется в `config/froghelper-roulette-timers.json` отдельно для каждого ника и продолжает отсчитываться после выхода; шахта и зеркало на него не влияют. Если голограмма показывает только часы и минуты, точность ограничена минутой. После окончания приходит локальное сообщение и всплывающее уведомление, затем повторяется каждые 10 минут по умолчанию. ПКМ по виджету позволяет отключить напоминания или задать интервал 1–1440 минут. Для уведомлений сам виджет добавлять не обязательно. После запуска уведомления приходят при входе на DW; пока Minecraft закрыт, уведомления не отправляются. После использования рулетки новый отсчёт запоминается при следующем обновлении видимой голограммы.

**Daily Credits Timer** работает отдельно от рулетки: при открытом меню автоматически считывает строку предмета «Новые кредиты через: …», включая `1д` и `23 ч. 11 мин.`. Наводить мышь на предмет не нужно. Сохранение — в `config/froghelper-daily-credits-timers.json`, отдельно по никам; отсчёт и напоминания продолжаются после закрытия меню и перезахода. Интервал и отключение напоминаний задаются через ПКМ по этому виджету независимо от рулетки. Истечение таймера означает окончание суточного ожидания; дополнительное требование сервера «Провести 1 час на режимах» виджет не проверяет.

### Что можно делать

- свободно двигать виджеты;
- привязывать их к экранным якорям;
- сцеплять один виджет с другим;
- переносить целые группы связанных элементов;
- менять масштаб каждого блока;
- сохранять персональную раскладку;
- добавлять и удалять виджеты, сохраняя их индивидуальные настройки для повторного использования.

### Управление в редакторе

| Действие | Как работает |
| --- | --- |
| Перемещение | зажать ЛКМ по виджету |
| Масштабирование | `Ctrl` + колесо мыши |
| Тонкая регулировка масштаба | `Ctrl` + `Shift` + колесо |
| Перетаскивание группы | удерживать `Alt` при начале перетаскивания |
| Свободное размещение, включая наложение | удерживать `Ctrl` при перетаскивании |
| Привязка к экрану / хотбару | поднести виджет к краю или центру; якорь также выбирается в настройках виджета |
| Добавить виджет | нажать `+` или его строку в боковой панели |
| Достать виджет из-под панели | перетащить его добавленную строку из списка |
| Скрыть/показать библиотеку | `Tab` в редакторе |
| Настройки виджета | ПКМ по виджету или его добавленной строке в библиотеке; `Esc` — обратно |
| Удалить виджет | нажать `-` в панели, крестик на виджете или `Delete` для выбранного |
| Сохранение позиции | автоматически после отпускания |

Магнит выравнивает близкие края и центры отдельно по X и Y, показывает направляющие и одинаковые промежутки. Выбранная цель удерживается до порога отлипания. Для группы учитывается общая рамка; участники группы исключаются из целей. Виджет можно свободно двигать вдоль края соседа: дальний угол не подтягивает его по другой оси.

Обычное перетаскивание останавливается у соседнего виджета и позволяет скользить вдоль его края, без новых пересечений. Для группы проверяются её отдельные участники. `Ctrl` отключает магнит и это ограничение: так можно намеренно наложить виджеты. Уже пересекающиеся виджеты из старой раскладки можно раздвинуть без автоматического выталкивания; после разделения повторный вход друг в друга ограничивается.

В `Widget → Snapping` доступны `Align only` (временное выравнивание) и `Connect / anchor` (сохранение связи при отпускании, стандартный режим), расстояния захвата/отлипания в экранных пикселях, отступ новых соединений, направляющие и типы целей. Порог не растёт при изменении GUI scale. Существующие связи сохраняют свой отступ. В настройках виджета можно выбрать экранный якорь, задать его смещение по X/Y или снять связь. Унаследованные виджеты Main служат целями без изменения основной раскладки.

### Основная раскладка

Основная раскладка — HUD по умолчанию, когда для текущей локации не назначена другая раскладка. Её нельзя удалить, переименовать или привязать к локации; состав виджетов, позиции и масштаб редактируются как обычно. При обновлении текущая раскладка сохраняется.

Нажмите название раскладки в заголовке боковой панели, чтобы переключиться или создать новую через `+ New layout`. Кнопка `...` рядом с названием дополнительной раскладки открывает её имя, `Include Main Layout widgets`, `Location visibility` и удаление. Дополнительная раскладка действует только в выбранных локациях; пустой список делает её неактивной в игре, но не мешает редактированию.

По умолчанию подходящая раскладка локации полностью заменяет основную: показываются только добавленные в неё виджеты. Пустая раскладка с назначенными локациями даёт пустой HUD. Если включить `Include Main Layout widgets`, к её составу добавляются виджеты Main. Общие виджеты показываются один раз с позицией и масштабом раскладки локации, остальные виджеты Main сохраняют основное размещение. В редакторе унаследованные виджеты Main показываются с пунктирной обводкой и более прозрачным фоном: к ним можно примагничивать свои виджеты, но их положение и настройки Main не меняются. Кнопка + в библиотеке добавляет такой виджет в дочернюю раскладку для собственного размещения; удаление возвращает его к унаследованному виду. Тумблер по умолчанию выключен, в том числе у сохранённых раскладок без этого поля. Если подходят несколько раскладок, используется последняя созданная подходящая; наследование добавляет только Main. Если подходящих нет, возвращается основная. При миграции старого конфига прежние виджеты переносятся в основную.

При автоматической смене раскладки после телепорта появление и исчезновение виджетов занимает 0,5 секунды. Виджет, который остаётся видимым, плавно меняет позицию и масштаб за 0,2 секунды. Повторный переход продолжает анимацию с текущего положения и прозрачности. При смене выбранной раскладки редактор сразу показывает её размещение; в конфиг сохраняются конечные координаты.

Переопределение позиции или масштаба виджета в дочерней раскладке не переносит за ним группу из Main: остальные унаследованные виджеты сохраняют своё размещение. Магнит к унаследованному виджету также не сдвигает Main при достижении края экрана.

В меню виджета по ПКМ есть `Location visibility` (виден только в выбранных местах) и `Location hidden` (скрыт только в выбранных местах). Режимы взаимоисключающие: выбор в одном очищает другой. Оба списка пустые — без ограничения локаций. Эти фильтры действуют во всех раскладках и не создают копий виджета.

Там же `Widget opacity (%)` меняет непрозрачность всего виджета, а `Background opacity (%)` — только подложки, её блюра и обводки. Диапазон 0–100%, по умолчанию 100% сохраняет текущий вид темы. Например, фон 0% оставляет текст и иконки без подложки; весь виджет 0% делает его невидимым. Настройки общие для всех раскладок, доступны также отдельным окнам чата и сочетаются с анимациями появления и исчезновения.

Выбор локаций поддерживает поиск по названию и серверному ID, группы локаций, `+ Current` и `Clear`. Введите точный ID и нажмите Enter, чтобы добавить отсутствующую локацию; суффикс `*` задаёт группу по префиксу ID. Названия показываются для удобства, совпадение проверяется по ID, полученному от DW. Пока локация неизвестна, разрешающий список скрывает виджет, запрещающий — оставляет его видимым.

Локация берётся из серверного `statisticinfo.gameLocation`. На JOIN мод сразу отправляет DW handshake; после Respawn без нового JOIN выполняет один объединённый запрос обновления, если новая локация ещё не поступила. При получении пакета раскладка применяется на первом следующем кадре.

В игре виджеты появляются, когда для них доступны данные и выполняются условия видимости. В редакторе выбранная раскладка показывается независимо от текущей локации и фильтров, включая preview без данных сервера.

Включение/выключение виджетов убрано из обычных настроек: состав раскладки меняется только в редакторе. Настройки конкретного виджета открываются по ПКМ на нём или его добавленной строке в библиотеке. У всех виджетов доступен масштаб; параметры содержимого показываются только для выбранного виджета. `Esc`, кнопка `< Back` или клик вне меню возвращают в редактор, изменения сохраняются автоматически. Общие настройки оформления остаются в меню `O`. Из раздела `Widget` можно перейти в редактор через `Edit Main Layout`.

`Ctrl+Z` отменяет последние 40 действий в редакторе раскладок и меню настроек. Один перенос, протягивание числа или изменение масштаба колёсиком до отпускания `Ctrl` считаются одним действием. Также можно отменить добавление/удаление виджетов и изменения настроек. История хранится только в памяти до закрытия меню; отменённое состояние сохраняется автоматически.

Числовые настройки меняются перетаскиванием самого числа влево/вправо. `Shift` уменьшает чувствительность в 10 раз. На изменения проигрывается короткий тик `scroll`, с общим ограничением 40 звуков в секунду.

Вверху меню настроек есть поиск по названиям настроек и разделов, без учёта регистра. Слева остаются разделы с совпадениями, справа — найденные настройки выбранного раздела. `Esc` очищает запрос; очистка возвращает прежний раздел и прокрутку. Поддерживаются вставка `Ctrl+V`, замена запроса через `Ctrl+A` и очистка через `Delete`.

`Ctrl+Backspace` полностью очищает активное текстовое поле в настройках и поиске, независимо от позиции курсора.

Звуки FrogHelper сопровождают открытие и закрытие меню, кнопки, переключатели, наведение, прокрутку и работу с виджетами. У появления босса, личных сообщений, находок и готовности умений свои сигналы. Громкость всех звуков мода регулируется ползунком **UI** в настройках звука Minecraft; общая громкость тоже действует. Звук подсказок алхимии по-прежнему можно отключить в её настройках.

Во время перетаскивания библиотека скрывается, освобождая весь экран для позиционирования. Внизу панели показывается только счётчик добавленных виджетов.

При добавлении виджет растёт от нулевого размера до своего масштаба за 0,2 секунды; при удалении уменьшается до нуля за 0,2 секунды. Анимация идёт от центра, вместе с фоном, текстом и иконками. Состав раскладки изменяется сразу, сохранённый масштаб остаётся прежним.

Добавление, удаление и изменение раскладки сохраняются автоматически. Удалённый виджет сохраняет настройки и последнее положение; при повторном добавлении он восстанавливается. Пустая раскладка также сохраняется и не заполняется заново после перезапуска.

## HUD и виджеты

Ниже перечислены основные HUD-элементы, которые мод умеет показывать игроку.

### Боссы и бой

| Виджет | Что показывает |
| --- | --- |
| **Boss Timers** | список боссов с таймерами возрождения |
| **Boss Bar** | кастомный блок с полосой босса |
| **Boss Damage** | ваш текущий или последний урон по боссу |
| **Ability Cooldowns** | откаты способностей |
| **Wand Cooldowns** | откаты палок / связанных умений |
| **Combo Progress** | текущий прогресс комбо |
| **Blocks/s** | скорость ломания блоков |
| **Estimated TPS** | клиентская оценка TPS сервера |

### Boss Timers

Настройки открываются по ПКМ на виджете. `Match player level` автоматически задаёт максимальный уровень босса по текущему уровню игрока DW; ручной максимум сохраняется для выключенного режима. Пока уровень неизвестен, используется ручное значение. Чёрный список и границы уровней действуют также на pop-up уведомления о респауне и захвате боссов.

Список боссов с обратным отсчётом до возрождения. Дополнительно:

- уже возродившийся босс какое-то время продолжает висеть с таймером «в минусе» и подсвечивается цветом Hard Accent (см. [Тему](#тема-и-внешний-вид)), а не пропадает мгновенно;
- диапазон уровней (`Min level` / `Max level`) настраивается; верхняя граница автоматически расширяется, когда сервер вводит боссов выше текущего потолка;
- источник данных выбирается между протоколом и миром (`Source mode`), плюс есть настройки иконок, имён, уровней и выравнивания.

### Wand Cooldowns

Таймеры посохов приходят из серверного протокола. Для Посоха Ветра, Посоха Вихря и локального названия `Величие гарпии` использование дополнительно отслеживается по предмету в руке, чтобы откат появлялся без ожидания следующего пакета.

Тумблер `Numeric Cooldown` заменяет полосу прогресса числом. В последнюю секунду оставшееся время показывается с десятыми долями секунды.

### Estimated TPS

Виджет показывает:

- текущий `TPS`;
- `1% low`;
- `0.1% low`.

Для него есть отдельный флаг `Enable Estimated TPS Monitor`. Если он выключен, мод вообще не собирает сэмплы и не тратит ресурсы на расчёт.

### Дополнительно по виджетам

В библиотеке виджетов доступен **Mining Statistics** — статистика текущей сессии добычи. Показывает время, блоки, деньги и шарды: итоги за сессию и оценку в час. Сессия хранится в памяти до закрытия Minecraft; переходы между локациями не сбрасывают её, выход с сервера приостанавливает, смена аккаунта сбрасывает. Блоки считаются по фактическому разрушению игроком, шарды и награды — по серверным сообщениям. Доход приблизительный: цена блока берётся из action bar, поэтому без `/autosell` выключи `Track mining money (autosell)`.

По ПКМ на виджете: ручная пауза/продолжение, сброс, бинды для этих действий и авто-пауза после настраиваемого простоя (по умолчанию 10 секунд). Для дохода можно отдельно учитывать блоки, бочки, руны, бомбы, питомцев, посохи и мультитул. Ручная пауза не снимается новыми наградами; авто-пауза снимается при продолжении добычи.

По умолчанию виджет выглядит как в EvoExtras: крупная кирка слева и три строки — время, добыча в час и итоги. Внешний вид: эта сводка, таблица, строки или компактные строки; отдельная видимость трёх ресурсов, итогов, показателей в час, времени, статуса, заголовка, подписей, иконок и заголовков столбцов. Настраиваются название, ширина, расстояние между строками, короткие/полные числа и десятичные знаки. Можно использовать цвета темы либо задать цвета отдельных элементов. Масштаб, прозрачность, фон, привязки и видимость по локациям работают через общие настройки виджетов. В Lightweight HUD иконки отключаются; текстовые расчёты обновляются пять раз в секунду.

- большинство виджетов можно свободно двигать и масштабировать;
- layout сохраняется между запусками;
- виджеты можно сцеплять и перемещать группами;
- для части виджетов есть compact-режим;
- для тяжёлых функций добавлены предупреждения о влиянии на производительность.
- FPS считает время между кадрами, включая VSync и ограничитель кадров. Lows — FPS по среднему времени самых медленных 1% / 0.1% кадров. Значения обновляются дважды в секунду, история ограничена 16 384 кадрами. Сбор работает только при видимом в раскладке FPS-виджете и активном окне игры; выход из мира или сворачивание сбрасывает историю.

### UnClutter

Тумблер `UnClutter (hide widget titles)` (категория `Widget`, включён по умолчанию) убирает подписи-названия внутри виджетов — остаются только сами данные (например, у `Active Runes` пропадает заголовок, остаются строки рун). Скрытие действует и в игре, и в редакторе, а фон и акцентная линия виджета остаются на месте. Виджеты, где верхняя строка сама по себе является данными (например `Level Progress`, `Combo Progress`), тумблер не затрагивает.

## Discord RPC

В FrogHelper встроен собственный Discord IPC-коннектор без внешних RPC-библиотек. При смене локации или подсервера обновление ставится в очередь на ближайшем клиентском тике, без ожидания интервала обновления прогресса. Работа с Discord остаётся асинхронной.

### Что показывает RPC

Discord Rich Presence умеет отображать:

- текущий сервер и зеркало;
- локацию;
- уровень;
- комбо;
- активный game event;
- elapsed time;
- режим активности по типу локации.

### Режимы активности

RPC автоматически подбирает статус и иконку в зависимости от ситуации:

| Режим | Что обычно означает |
| --- | --- |
| `froghelper` | нейтральный fallback |
| `hub` | хаб / спавн / лобби |
| `mine` | шахта |
| `dungeon` | данж |
| `siege` | осада |
| `boss` | босс |
| `fishing` | рыбалка |
| `death` | смерть / ожидание респавна |
| `event` | маленькая иконка активного ивента |

### Privacy Mode

Есть отдельный `Privacy mode`.

В нём RPC почти пустой:

- базовая иконка `froghelper`;
- строка `FrogHelper`;
- без сервера, локации, событий и прочих деталей.

### Настройки Discord

Во вкладке `Discord` можно управлять:

- `Enable auto RPC`
- `Privacy mode`
- `Show elapsed time`
- `Show server`
- `Show mirror`
- `Show location`
- `Show level`
- `Show combo`
- `Show game event`

## Чат и общение

Одинаковые сообщения подряд схлопываются в одну строку с меткой `[x2]`, `[x3]` и далее — в основном чате, FH и вкладках-виджетах. Время сообщений не мешает объединению. Сообщения разных авторов, источников или с разными кликабельными действиями остаются отдельными. Настройка **Render → Collapse repeated messages** включена по умолчанию. Оригинальные сообщения сохраняются для игровых обработчиков и штатного удаления сообщений.

### Обмен конфигами

В социальном меню (`C`) кнопка **Конфиг** скачивает основной конфиг игрока. В настройках → **Configs** можно выбрать скачанный конфиг или удалить его. **Мой основной конфиг** нельзя удалить; скачивание и выбор чужого конфига его не перезаписывают. Изменения сохраняются в выбранный конфиг. При удалении активного скачанного конфига включается основной. Выбранный конфиг сохраняется между запусками.

Передаются настройки мода, бинды FrogHelper, виджеты, раскладки, позиции, масштабы, внешний вид и вкладки чата (названия, фильтры, порядок и размещение). История чата, сведения о кланах, игровые таймеры, аккаунты и токены не передаются. Локальная библиотека `config/froghelper-profiles` хранит до 32 скачанных конфигов. Backend выдаёт конфиги только авторизованным игрокам онлайн в том же регионе; размер ограничен 128 КиБ. Для обмена нужно обновить мод и backend.

### Вкладки чата

Сообщения автоматически раскладываются по вкладкам:

- общий чат;
- приваты;
- отдельные категории по префиксам и типам сообщений.

### Вкладки, поиск и отправка

Игровые вкладки `ALL / G / T / L / C / PM` используют общую ограниченную историю сообщений. `ALL` закреплена первой слева, `FH` — второй; их нельзя переместить, отделить, изменить или удалить. `FH` содержит только общий чат FrogHelper через backend и не включается в `ALL`. Новые входящие сообщения FH вызывают всплывающее уведомление с ником и текстом; настройка `Pop-Ups → Event: FH message` включена по умолчанию. Свои сообщения, загрузка истории и повторная доставка не вызывают уведомлений. Переключение сохраняет исходные сообщения, их время, подпись и источник, а также положение прокрутки каждой вкладки. Дополнительная история прибавляется к базовым 100 сообщениям; значение `0` оставляет базовую историю.

- Счётчики возле названий вкладок показывают непрочитанные сообщения именно этой вкладки, с учётом её канала, фильтра и `Skip Others`. Открытие вкладки отмечает её сообщения прочитанными; `ALL` также отмечает их в остальных вкладках, но не затрагивает скрытые от неё сообщения и историю FH. Удалённые из истории сообщения не остаются в счётчиках; загрузка старой истории FH и повторная доставка сообщений счётчик не увеличивают.
- `Ctrl+Tab` переключает вкладки, `Ctrl+Shift+Tab` — в обратном порядке.
- Кнопка `Поиск` или `Ctrl+F` открывает поиск по текущей вкладке без учёта регистра. Поиск скрывает несовпадающие строки, сохраняя историю. `Esc` или `Enter` возвращает к исходному вводу; поисковый запрос не отправляется в чат.
- На DW обычный текст отправляется в выбранный канал: `G` — глобальный, `T` — торговый, `C` — клановый. `ALL` и `L` сохраняют обычную отправку. Команды и явно введённые префиксы не изменяются.
- Во вкладке `PM` используется команда ответа, если сервер объявляет `/r` или `/reply`. Иначе укажи адресата явно: `/m Ник сообщение`. Текст из `PM` не отправляется в публичный чат при отсутствии команды ответа.

Переносы строк кэшируются с ограничением памяти. Переключение вкладок не запускает игровые обработчики повторно. При изменении ширины или масштаба чата кэш переносов обновляется.

### Вкладка как виджет

Вкладки остаются в нижней полосе основного чата. Зажми обычную вкладку (кроме `ALL` и `FH`) ЛКМ и вытягивай на экран — она превратится в отдельное окно. Чтобы вернуть её, перетащи заголовок окна обратно к полосе вкладок. Обычный клик ничего не отделяет. Перетаскивание вдоль полосы меняет порядок вкладок; у края полоса прокручивается автоматически. Порядок сохраняется, `Ctrl+Tab` следует ему.

- `+` создаёт новую вкладку; ПКМ по вкладке или заголовку окна (кроме `ALL` и `FH`) открывает имя, канал и текстовый фильтр, ширину и число строк.
- Колесо над окном плавно прокручивает только его: шаг равен половине видимых строк, `Shift` уменьшает его до одной строки. Дробные движения колеса/тачпада учитываются. При изменении ширины, высоты и масштаба сохраняется читаемое сообщение. Клик по окну выбирает канал отправки, сохраняя вкладку основного чата. `Ctrl+F` ищет в выбранном окне.
- ПКМ по сообщению копирует его, ссылки и команды остаются кликабельными. Окна используют общую историю без повторной обработки сообщений.
- `Fixed chat widget font` в настройках чата сохраняет размер шрифта при масштабировании окна: меняются доступная ширина и число видимых строк. В режиме `Bare` у окон остаётся лёгкое чёрное затемнение, связанное с прозрачностью фона текста Minecraft.
- `Widget visibility` в настройках вкладки-виджета: `Always` оставляет окно видимым постоянно; `Chat open` показывает его при открытом основном чате или на 10 секунд после нового сообщения этого канала с учётом фильтра, с затуханием в последние 2 секунды. Загрузка истории FH окно не включает; в редакторе виджет всегда доступен.
- `Message sound` (по умолчанию выключен) проигрывает `toggle.ogg` при новом сообщении, подходящем под канал и текстовый фильтр окна. Работает для отделённых окон текущей раскладки, включая временно затухшие; загрузка истории и перерисовка чата звуков не вызывают. Если сообщение подходит нескольким окнам, звук один. Громкость регулируется настройкой UI Minecraft.
- `Skip Others` (по умолчанию выключен) убирает совпавшие с каналом и текстовым фильтром вкладки сообщения из `ALL` и следующих вкладок по порядку полосы. Предыдущие обычные вкладки продолжают получать их. Работает и для отделённых окон; заблокированные сообщения не включают их видимость или звук. Настройка доступна по ПКМ на обычной вкладке. Отключение возвращает сообщения из общей истории.
- Отделённое окно участвует в редакторе `H` и раскладках. Настройки видимости по локациям доступны для вкладок, кроме `ALL` и `FH`. В библиотеке редактора доступны только уже отделённые окна.
- Если вкладки не помещаются в полосу, прокручивай её колесом. Любую вкладку, кроме `ALL` и `FH`, можно настроить и удалить, включая стандартные `G / T / L / C / PM`. `ALL` и `FH` закреплены слева и не имеют настроек.

### Чат FrogHelper (FH)

Вкладка `FH` отправляет и получает сообщения только через `https://cclu.alwaysdata.net` с существующей автоматической авторизацией DW. Префиксы `!`, `$`, `@` и `/` здесь являются обычным текстом: игровые команды, чат и запросы автодополнения на сервер Minecraft не отправляются. Без доступного backend отправка блокируется.

История общая для игроков с модом на разных подсервах и зеркалах. PostgreSQL сохраняет последние **5000 сообщений** после перезапуска backend. Клиент загружает последние 32 сообщения, старые страницы — при прокрутке вверх; новые приходят через уведомление WebSocket и запрос страницы. Ник и время назначает backend; проверка времени ответа использует часы backend независимо от часов ПК. Сообщение ограничено 256 символами; не чаще одного сообщения раз в несколько секунд. При неподтверждённой отправке текст доступен через ↑ в истории ввода.

Для работы FH нужно обновить и мод, и backend. На старом backend остальные вкладки и социалка продолжают работать.

При подключённом Discord-мосте сообщения FH передаются в выбранный текстовый канал с пометкой `[Minecraft]`, а сообщения пользователей этого канала появляются в FH с иконкой Discord перед ником. Боты и webhook-сообщения обратно не пересылаются. История остаётся общей, с прежним лимитом 5000 сообщений. Discord-текст отображается буквально, без выполнения команд или кодов форматирования.

Из FH можно упоминать Discord-роли (`@Nexus`, `@"Роль с пробелами"`) и пользователей по Discord username или серверному нику (`@Fox`). Совпадение должно быть точным; имена ролей проверяются первыми, совпадающие имена нескольких ролей или участников остаются текстом. Поддерживаются и явные Discord-упоминания по ID. Упоминания в коде, ссылках и адресах почты не преобразуются. Для уведомления участников роли в Discord она должна быть доступна для упоминания либо бот должен иметь право Mention Everyone. Это же право нужно для `@everyone` / `@here`; доставка уведомлений также зависит от настроек получателя.

Кнопка `↑` справа в полосе вкладок при выбранной FH открывает отправку картинки: перетащи PNG/JPEG в окно, укажи путь или выбери последний скриншот `F2`, добавь подпись и нажми «Отправить». Лимит — 4 MiB; PNG до 4 мегапикселей, JPEG до 16 мегапикселей. Входящие картинки показаны кликабельными названиями: ЛКМ открывает изображение в игре, `Esc` возвращает в чат. Если метаданные вложения появились с задержкой, последние сообщения повторно проверяются и ссылка добавляется в существующее сообщение, без дубля или повторного pop-up. Загрузка и декодирование выполняются в фоне только при открытии, изображение ограничивается 1280 пикселями по длинной стороне; JPEG уменьшается уже при декодировании, без полноразмерной текстуры. При закрытии текстура освобождается. Автоматической загрузки всех картинок истории нет.

### Метки времени

Каждое сообщение можно снабжать временем в формате `HH:mm:ss`, чтобы было легче понимать, когда именно произошло событие.

### Tone Down Chat

Опция делает чат визуально спокойнее:

- убирает часть визуального шума;
- уменьшает агрессивную декоративность;
- делает переписку аккуратнее и легче читаемой.

### Копирование сообщений

ПКМ по строке чата копирует тело сообщения без timestamp, канального префикса, ранга и ника отправителя. Поведение включается тумблером `Copy chat by RMB`.

При включённом `Full Message Copy` копируется полная отображаемая строка: timestamp, канал, ранг, ник и текст. Внутренние служебные символы FrogHelper в буфер обмена не попадают.

После копирования можно получить pop-up уведомление.

Для копирования нескольких сообщений зажмите ПКМ и проведите по нужным строкам.
`Ctrl+ПКМ` добавляет или убирает отдельное сообщение, `Shift+ПКМ` выделяет диапазон.
При отпускании ПКМ выбранные сообщения копируются от старых к новым с переносом
строки между ними; `Ctrl+C` повторно копирует выделение. Перенесённое на несколько
строк сообщение копируется целиком один раз. Работает и в обычном чате, и в
вкладках-виджетах. ЛКМ и закрытие чата снимают выделение.

В **Render → Utility** у `Chat timestamps` есть настройки формата 12/24 часа,
секунд, скобок, цвета темы или собственного цвета, жирного шрифта и курсива.
Предпросмотр показывает результат сразу; настройки применяются к новым сообщениям
обычного чата, FH и вкладок-виджетов.

### Auto Thanks

Если кто-то активировал глобальный бустер, мод может автоматически отправить `thx`.

### Приваты и pop-up уведомления

На входящий приват можно получить отдельный pop-up:

- с превью текста;
- без необходимости постоянно держать чат открытым.

### Обмен таймерами боссов

Таймеры боссов запрашиваются кнопкой «Таймеры» напротив игрока в социальном меню (`C`). Обмен идёт через авторизованный backend; игровые сообщения для передачи не используются.

### Пользователи FrogHelper и Socials

После входа на DW FrogHelper автоматически авторизуется на backend и получает список пользователей мода по WebSocket. Социалка работает всегда; отдельного тумблера `Socials` нет. Старые выключенные значения `socialsEnabled` и `modUserMesh` в конфигурации игнорируются.

Клавиша `C` открывает список игроков с модом онлайн. В нём рядом с ником показано `Nick [N]`, где N — количество активных таймеров боссов в выбранном режиме источника (без фильтров/лимита строк HUD). Кнопка справа запрашивает таймеры через backend у любого игрока, в том числе на другом подсервере или зеркале. Метка `P` возле жабки означает Protocol Only и больше 50 таймеров; наведите мышь для подсказки. Полученные таймеры дополняют отсутствующие, собственные данные сервера/мира имеют приоритет. Свежесть ответа проверяется по времени backend, оставшееся время респауна переносится на часы клиента. При ошибке меню различает HTTP-ответ, сбой сети и некорректные данные; подробности записываются в `latest.log` без токенов. Старые клиенты без данных показываются с `[—]`. Значок жабки в TAB, чате и над игроком служит визуальным оформлением; настройка `FrogHelper Badge On Nametags` управляет отображением над игроком.

Backend создаёт Discord embed при входе и обновляет его при переходах и выходе. Адрес webhook настраивается на сервере. Смена локации обходит обычные интервалы обновления метаданных и embed. Лимит отправки в API (не чаще одного кадра в секунду), последовательная доставка, повторы после ошибок и ограничения Discord сохраняются.

## Оверлеи и подсветка

Масштаб панелей внутри инвентаря настраивается отдельно от HUD: `Fish experience scale %` в `Fishing`, `Rune set stats scale %` в `Runes Bag Keybinds` и `Auto-brewing cost scale %` в `Alchemy`. Диапазон — 50–300%, по умолчанию 100%; масштабируется весь блок вместе с текстом и фоном. На маленьком экране слишком большая панель уменьшается до размеров окна.

### Fishing

Рыболовный блок умеет:

- показывать рыболовные метки по серверным пакетам `BUBBLE`, `LAVA`, `DUST` и прежним вариантам пузырьков; метки работают и при минимальном количестве частиц;
- выводить виджет по клёву;
- использовать данные протокола по fishing spots;
- показывать полупрозрачный поплавок в прогнозируемой точке заброса: Fishing → Cast preview (по умолчанию выключено). Учитываются вода, формы блоков и зацепы за сущности (включая выброшенные предметы); маркер следует за выбранной сущностью. Расчёт ограничен 10 разами в секунду и 120 шагами, не создаёт сущностей и прекращается после заброса. Небольшой случайный разброс сервера и движение цели за время полёта могут отличаться от прогноза;
- автоматически дёргать удочку при срабатывании, если включён Auto Fish.

### Алхимия

Подсвечивает ингредиенты алхимии прямо в мире.

### Данжи и осады

Поддерживаются:

- карта данжа / осады;
- подсветка важных декоративных элементов и ориентиров.

### Полосы HP игроков

Мод умеет рисовать полосы здоровья над игроками:

- с настройкой прозрачности;
- с вертикальным смещением;
- с плавным затуханием по дистанции;
- с настройкой размера самой полоски (`Bar size %`).

Когда здоровье игрока опускается ниже настраиваемого порога (`Hard accent threshold %`), полоса уходит «в красное» — смещается к цвету Hard Accent. Насколько резко происходит смена цвета, задаётся ползунком `Accent strength %`: при высоком значении переход читается чётко, а не еле заметным затуханием.

### Useful Items Highlight

Подсветка полезных объектов и предметов помогает быстрее замечать важные точки в мире.

Уведомление и звук обнаружения кристалла срабатывают один раз для его координат в текущей локации. Выгрузка чанка и телепорт внутри той же шахты не повторяют уведомление; память обнаружений сбрасывается при смене локации, подсервера/зеркала или отключении от сервера.

## Автоматизация и утилиты

### Auto Messages

Система авто-сообщений позволяет настроить слоты с сообщениями, которые будут отправляться по таймеру.

Для каждого слота задаются:

- текст;
- активность;
- задержка в секундах.

### Clicker

Позволяет включить авто-нажатие с заданной скоростью.

Настройки:

- CPS;
- режим атаки;
- режим использования предмета вместо атаки.
- `Clicker activation`: `Toggle` включает/выключает кликер нажатием бинда; `Hold` работает только пока бинд удерживается. При открытом меню или неактивном окне клики приостанавливаются.

### Auto Fish

Полуавтоматическая рыбалка:

- отслеживает состояние поплавка;
- ждёт нужное количество тиков;
- автоматически делает нужное действие.

### Boss Respawn Messages

Мод умеет локально уведомлять о важных этапах босса:

- сообщение перед респавном;
- сообщение о спавне;
- сообщение о проклятии;
- сообщение о низком HP.

В отдельном разделе **Low HP Message** есть конструктор с цветным предпросмотром.
Подсервер, имя, уровень, проклятие, HP, процент HP и подпись стадии можно скрывать
независимо друг от друга. Цвет каждого элемента задаётся кодом `&0`–`&f`
(также принимается `§0`–`§f`). Настройки общие для локального и кланового сообщения.
Пример: `[PE1.2] Бессмертный Легион [130] — 125❤ (20%) [Стадия 2/4]`.
При скрытии всех элементов сообщение не отправляется.

### Pop-Ups

Встроенная система всплывающих уведомлений сообщает о событиях вроде:

- входящего привата;
- появления босса;
- готовности способности;
- готовности wand-умения;
- готовности продавца;
- возвращения майнера;
- окончания отката набора рун;
- окончания зелья;
- окончания бустера;
- копирования чата.

Дополнительно настраиваются:

- число одновременно видимых pop-ups;
- длительность показа;
- скорость появления;
- скорость исчезновения.

## Тема и внешний вид

Мод поддерживает несколько пресетов темы интерфейса:

- `Frog`
- `Mint`
- `Ember`
- `Ocean`
- `Custom`

Через тему меняются:

- акцентные линии;

### Hard Accent

Отдельный «критический» цвет, настраиваемый в категории `Theme` тремя ползунками (`Hard accent red / green / blue`). Он не зависит от выбранного пресета и остаётся ярким на любой теме. Hard Accent применяется ровно к двум местам:

- таймер босса, ушедший «в минус» (уже возродившийся босс);
- полоса HP игрока, опустившаяся ниже порога критического здоровья.

### Visuals

В **O → Render → Clear substances** доступны независимые `Clear Water`, `Clear Lava` и `Clear Powder Snow` (по умолчанию выключены). Они убирают туман соответствующей среды; вода также лишается экранной пелены, лава — огня на экране при погружении, рыхлый снег — морозной рамки. Действуют сразу, без перезапуска. Урон, горение и замерзание сохраняются.

Откройте **O → Visuals** и выберите группу в строке **Section**:

**Reset section** возвращает выбранную группу к стандартным настройкам. **Reset All Visuals** сбрасывает все группы Visuals. Оба действия можно отменить через `Ctrl+Z`, пока меню открыто.

- **Screen** — соотношение сторон (включая Custom), независимое растяжение руки,
  компактная полоса перезагрузки ресурсов вместо перекрывающего игру экрана.
- **Crosshair** — крест, X, круг, квадрат или точка; размер, плечи, обводка,
  инверсия, цвет цели, динамический разброс и индикация натяжения лука/арбалета/трезубца.
- **Hitboxes** — все сущности, живые или игроки; свой бинд, переоформление F3+B,
  заливка, цвета цели/получения урона, линия глаз и направление взгляда.
- **Block outline** — точная форма или рамка, обычные/неоновые/пунктирные линии
  и уголки, заливка, сквозное отображение, радуга, движение и затухание.
- **Hand** — отдельные смещения, поворот и масштаб рук, зеркалирование,
  скорость взмаха, анимация смены предмета и FOV руки. Существующий Static Hand сохраняется.
- **Camera** — Freelook по удержанию или нажатию, вид спереди, инверсия,
  расстояние свободной камеры и обычного третьего лица. Бинд задаётся здесь.
  Во время Freelook колесо вниз отдаляет камеру, вверх приближает: шаг 0,5 блока,
  диапазон 0,5–20. Хотбар не переключается. `Remember last distance` включён по умолчанию: следующая активация начинается с последней дистанции, которая сохраняется между запусками. Если выключить переключатель, камера каждый раз стартует с `Freelook distance`; колесо меняет дистанцию только до выхода из Freelook.
- **World** — яркость до 200%, оттенки освещения, время и погода, цвета неба/облаков,
  режим и дальность тумана в воздухе и размер/сила теней сущностей.
- **Tab** — страницы и размеры списка, курсор, выделение и меню игрока.
  После включения Custom TAB удерживайте **Tab** и нажмите **среднюю кнопку мыши**.
  Колесо и A/D/стрелки листают страницы; Esc или повторный бинд закрывает курсор.
  Меню позволяет открыть DW statistics/profile, подготовить `/m` или скопировать чистый ник.

В группах есть лёгкие иллюстрации настроек; нажмите на превью для смены сценария.
Превью рук показывает смещения и масштаб; полный поворот/FOV видны в игре.
Все новые эффекты включаются отдельно и по умолчанию выключены. При обновлении
сохраняются ранее настроенные цвета и соотношение сторон. Числа перетаскиваются,
Shift замедляет изменение; поддерживаются бинды с Ctrl/Shift/Alt.
Чтобы удалить бинд, нажмите ПКМ по его полю или начните назначение ЛКМ и нажмите Esc.
Модификаторы тоже очищаются, меню остаётся открытым; сброс можно отменить через Ctrl+Z.

Для цветов с прозрачностью используется **#AARRGGBB**: AA=00 — прозрачно, AA=FF — непрозрачно.
Небо, туман и оттенки света используют RGB. Изменения времени/погоды относятся только к клиенту.
Обычный FOV Minecraft теперь можно поднять до 150; FOV руки регулируется независимо.
Игровые функции работают без установки EvoPlus, EvoVisuals или Kotlin runtime.

## Профайлер

В FrogHelper встроен собственный семплирующий профайлер. Он нужен, чтобы **точно** понять, какая часть мода нагружает клиент, а не гадать — именно через него в несколько итераций оптимизировалась подсветка мира. Это в первую очередь инструмент для диагностики просадок FPS и фризов.

### Ключевые свойства

- **Выключен по умолчанию**. Флаг **Render → Visual → Debug** включает только минимальный фоновый сбор в памяти, в том числе в главном меню. Подробные замеры и запись на диск запускаются вручную через `/fhprof start`. При выключенном Debug и отсутствии ручной сессии замеры и периодические снимки не собираются.
- Ручные отчёты сохраняются локально. Если на DW FPS держится ниже 15 не менее 5 секунд, мод автоматически собирает 15-секундный профиль и отправляет диагностический архив на backend; свежий краш-лог отправляется после следующего входа. Backend публикует их через DISCORD_ERROR_WEBHOOK_URL.
- Замеряет именованные участки кода (секции) и счётчики событий по всему моду: рендер, HUD, отдельные виджеты, тики, обработку протокола и т. д. Применение раскладки (`hud/layout/apply`), анимации (`hud/animation/`) и боковая панель (`ui/widgetSidebar/render`) имеют отдельные замеры; добавление и удаление виджетов отмечаются в журнале событий.
- Фоновый сбор остаётся минимальным: снимки памяти, FPS и доступных счётчиков примерно раз в 10 секунд, ограниченная история событий подключения. Debug не создаёт файлы и не запускает JFR; накопленные данные можно сохранить командой `/fhprof dump`. Автоматический сбор не перебирает сущности и чанки, не строит гистограмму кучи. Подробные типы объектов мира доступны в ручном отчёте.


### Лёгкий HUD для слабых компьютеров

В настройках **Widget → Core → Lightweight HUD (no blur / item icons)** можно
отключить блюр, сглаженные панели и модели предметов во всех виджетах FrogHelper.
Текст, таймеры, действия виджетов и их расположение сохраняются. Эта настройка не
меняет обычный инвентарь Minecraft, модели в мире и настройки других модов.
По умолчанию режим выключен; включение не требует перезапуска игры.

Имена и объединённые списки таймеров боссов кешируются до изменения данных;
строки отсчёта обновляются при изменении отображаемой секунды. Смена сроков,
имён и иконок, истечение таймера и смена настроек учитываются при обновлении.
Проверка размеров закреплённых виджетов во время игры выполняется до 10 раз в секунду;
редактор продолжает пересчитывать расположение на каждом кадре.

### Команда `/fhprof`

| Команда | Что делает |
| --- | --- |
| `/fhprof status` | состояние, режим (`debug-memory`, `manual`, `debug-memory+manual`), число секций и счётчиков, длительность и путь записи |
| `/fhprof start` | сбрасывает статистику, включает подробные замеры и запись на диск; история фоновых снимков сохраняется |
| `/fhprof stop` | останавливает подробные замеры и запись на диск; при включённом Debug минимальный сбор в памяти продолжается |
| `/fhprof reset` | очищает накопленную статистику |
| `/fhprof report [prefix]` | выводит топ секций и счётчиков прямо в чат |
| `/fhprof dump [prefix]` | сохраняет Markdown-отчёт без принудительной гистограммы кучи |
| `/fhprof dump-full [prefix]` | дополнительно собирает гистограмму классов JVM; может временно заморозить игру |

Без аргументов `/fhprof` эквивалентен `/fhprof status`.

Типичный сценарий: `/fhprof start` → поиграть в проблемной ситуации 20–60 секунд → `/fhprof dump` → открыть сохранённый файл.

### Фильтр по префиксу

Секции именуются с префиксами: `render/`, `hud/`, `widget/`, `tick/`, `ui/`, `world/`, `protocol/`, `visuals/`. Настройки Visuals включаются в environment.json подробной сессии. Необязательный `prefix` в `report` и `dump` оставляет только совпадающие секции — удобно сфокусироваться на подсистеме:

```text
/fhprof report render/
/fhprof dump render/UsefulWorldHighlightRenderHook
```

### Куда сохраняется отчёт

`/fhprof dump` пишет файл в папку `froghelper-profiler` внутри директории игры:

```text
<game>/froghelper-profiler/fhprof-<дата-время>.md
```

При использовании фильтра имя файла содержит префикс: `fhprof-<prefix>-<дата-время>.md`. Путь к сохранённому файлу выводится в чат.

`/fhprof start` запускает сохранение контрольных копий для восстановления после краша
и создаёт папку `froghelper-profiler/fhprof-live-<дата-время>-<pid>-<номер>`.
`/fhprof stop` сохраняет финальное состояние ручной сессии независимо от Debug.
Если сейчас идёт автоматический 15-секундный профиль, он заканчивается по своему таймеру.
Выключение Debug останавливает только фоновый сбор в памяти; явно запущенная ручная сессия продолжается до `/fhprof stop`.
Без Debug, ручной сессии и автоматического события FPS диагностика не собирается. В папке ручной сессии находятся:

- `environment.json` — версия Java, параметры JVM и установленные моды;
- `events.jsonl` — события переходов, снимки клиента и память JVM/системы; фоновая запись примерно раз в секунду продолжается при зависшем клиенте;
- `report.md` — автоматически обновляемый Markdown-отчёт примерно раз в 5 секунд;
- `profile.jfr` — JFR последних двух минут с ограничением хранения 32 MiB, обновляемая примерно раз в 5 секунд.

JFR запускается самим модом для ручной сессии `/fhprof start` либо автоматического профиля при низком FPS, с настройками `default`; отдельный `-XX:StartFlightRecording` для этой записи не нужен.
Чтобы включить также учёт нативной памяти JVM в JFR, можно добавить
`-XX:NativeMemoryTracking=summary` при запуске Java. Уже запущенные внешние записи JFR мод не останавливает.

Готовые `report.md` и `profile.jfr` заменяются только после полной записи новой копии.
Сохранённые данные остаются даже при принудительном завершении JVM без shutdown hook;
последние несохранённые секунды могут потеряться. Последняя строка журнала может быть
оборвана крашем — при чтении учитываются только законченные JSON-строки.
Журнал ограничен двумя файлами примерно по 8 MiB: `events.jsonl` и `events.previous.jsonl`.
При остановке профайлера сохраняется финальная копия. Путь и ошибки автосохранения
можно посмотреть через `/fhprof status`. `/fhprof dump` сохраняет отдельный отчёт без тяжёлой гистограммы классов.
Гистограмма доступна через `/fhprof dump-full`: JVM останавливает потоки для её сбора,
поэтому такую команду лучше запускать вне боя. Автоматические контрольные копии гистограмму не собирают.

### Автоматические отчёты об ошибках

Если FPS остаётся ниже **15** непрерывно **5 секунд** в активном окне во время игры
на DW, мод автоматически собирает **15 секунд** подробного профиля и JFR.
Восстановление до 15 FPS, потеря активности окна или выход из игры сбрасывают подтверждение. Debug включать не требуется. Запись останавливается
таймером вне игрового потока, даже если клиент завис. Ручная сессия `/fhprof start`
продолжает работать: автоматический отчёт содержит отдельное окно замеров из той же записи.
Новый профиль возможен не чаще раза в **10 минут** и после восстановления до 20 FPS
как минимум на 5 секунд; постоянная просадка не создаёт бесконечные отчёты.

При запуске проверяется последний `crash-reports/crash-*.txt` или `hs_err_pid*.log`.
Нативные логи из рабочей/временной директории проверяются на принадлежность Minecraft
и этой игровой директории, если она указана. Отчёт отправляется после автоматической
авторизации на DW. Уже принятый краш повторно не отправляется; исходный лог сохраняется.
Принудительное завершение процесса не всегда создаёт краш-лог: отсутствующий файл
мод восстановить не может. Общий `latest.log` с чатом не отправляется.

ZIP с отчётом передаётся по HTTPS на собственный backend с действующей сессией;
backend отправляет embed и вложение через серверную переменную `DISCORD_ERROR_WEBHOOK_URL`.
Адрес webhook отсутствует в клиенте. Токены, пароли и webhook-адреса скрываются в
текстах; из отправляемого JFR исключаются события с аргументами запуска и переменными среды.
Упаковка и сеть работают вне игрового потока. После успешной упаковки временная
автоматическая запись удаляется; файлы ручной сессии сохраняются.

При потере связи архив остаётся в `<game>/froghelper-profiler/diagnostics` и отправляется
повторно с паузой. Очередь ограничена **8 архивами / 32 MiB**, архив — **8 MiB**.
Если JFR не помещается, отправляется текстовый отчёт с объяснением. Когда очередь полна,
новые автоматические записи не запускаются. В обычной игре постоянной записи на диск нет:
Debug по-прежнему хранит только минимальные снимки в памяти.

### Что внутри отчёта

Markdown-отчёт удобно читать/прикладывать при разборе проблем. В нём:

- **Session Context** — версии FrogHelper / Minecraft / Fabric Loader, окружение, сервер, экран, измерение, ник, FPS, размер окна;
- **Summary** — главные горячие точки (по суммарному времени, по self-времени и самый большой одиночный спайк);
- таблицы **Top Sections** — по суммарному времени, по self-времени и по максимальным спайкам;
- **Call Tree** — дерево вложенных замеров;
- **Recent / Worst Samples** — история недавних и худших кадров/тиков;
- **Top Counters** — счётчики событий;
- **Legend** — расшифровка метрик.

### Метрики

| Метрика | Смысл |
| --- | --- |
| `calls` | сколько раз секция была измерена |
| `total` | суммарное время в секции |
| `self` | время в секции без вложенных измеренных участков |
| `avg` | среднее время на вызов |
| `max` | худший одиночный спайк |
| `share` | доля секции от всего измеренного времени |
| счётчики (`events` / `total`) | число событий и накопленные «единицы работы» — это не время, а количество (например, сколько чанков просканировано) |

## Команды мода

### `/fhproto`

Показывает диагностику серверного протокола:

| Команда | Что делает |
| --- | --- |
| `/fhproto` или `/fhproto stats` | выводит текущую статистику пакетов |
| `/fhproto anomalies` | показывает обнаруженные аномалии декодирования |
| `/fhproto reset` | сбрасывает накопленную диагностику |

### `/fhprof`

Управление встроенным профайлером производительности. Подробности и подкоманды — в разделе [Профайлер](#профайлер).
