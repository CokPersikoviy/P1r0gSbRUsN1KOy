## Что даёт мод

FrogHelper собирает важную игровую информацию в одном месте и показывает её прямо во время игры:

- таймеры боссов, способностей, посохов, зелий, продавцов и майнеров, а также состояния рун и питомцев;
- прогресс уровня и комбо;
- удобные HUD-виджеты с редактором расположения и режимом UnClutter;
- переключение наборов рун по настраиваемым хоткеям;
- карта данжа/осады, рецепты, fishing-информация, pop-up уведомления;
- улучшения чата и внутриигровой обмен данными между игроками с FrogHelper;
- Quick Access для быстрых команд по удержанию одной клавиши;
- ESP и подсветка полезных объектов;
- Discord Rich Presence с игровым контекстом;
- локальные уведомления о важных событиях.

## Быстрый старт

После входа в игру полезно знать несколько основных действий:

| Действие | По умолчанию |
| --- | --- |
| Включить режим редактирования HUD | `H` |
| Открыть меню настроек | `O` |
| Открыть Quick Access | удерживать `R` |
| Включить / выключить авто-кликер | `K` |

Дополнительно:

| Действие | По умолчанию |
| --- | --- |
| `clanhide` | `Z` |
| `runesbag` | `X` |

## Основные хоткеи

### `H` — Editing Mode

Открывает режим редактирования HUD. В нём можно:

- двигать виджеты;
- менять масштаб;
- привязывать их к якорям экрана;
- сцеплять виджеты между собой;
- таскать связанные группы;
- добавлять виджеты из боковой панели и удалять их из основной раскладки.

### `O` — Settings Menu

Открывает внутреннее меню настроек FrogHelper. Через него настраиваются:

- виджеты;
- Quick Access;
- чат;
- pop-ups;
- fishing;
- render и highlight-опции;
- Discord RPC;
- темы;
- clicker и другие утилиты.

### `R` — Quick Access

Работает по принципу удержания:

1. зажимаете `R`;
2. наводитесь на нужную команду;
3. отпускаете клавишу;
4. команда выполняется автоматически.

### `K` — Clicker

Переключает авто-кликер. Он может:

- бить как обычная атака;
- использовать предмет вместо атаки;
- работать с заданным CPS.

### `Z` — Clan Hide

Отправляет команду `clanhide`.

### `X` — Runes Bag

Отправляет команду `runesbag`.

### `1`–`7` — выбор набора рун

При открытом окне рун-мешка эти клавиши переключают активный набор рун (1–7). Также работают стрелки `←` / `→` для перебора наборов.

Клавиши переназначаемые: `Options → Controls → категория FrogHelper → Rune Set 1…7`. По умолчанию — цифры `1`–`7`. Они срабатывают только внутри окна рун-мешка, поэтому не конфликтуют с выбором слотов хотбара в обычной игре.

## Редактор HUD

Редактор HUD нужен для полной подгонки интерфейса под себя.

У новых пользователей основная раскладка пустая. При обновлении текущие видимые виджеты автоматически переносятся с сохранением позиций, масштаба и привязок. Ранее отключённые или свёрнутые виджеты остаются в библиотеке для повторного добавления.

Боковая панель содержит все 27 виджетов, поиск и прокрутку. Нажмите `+` или строку отсутствующего виджета, чтобы добавить его. Панель можно свернуть стрелкой в заголовке, чтобы добраться до виджетов у левого края экрана.

### Что можно делать

- свободно двигать виджеты;
- привязывать их к экранным якорям;
- сцеплять один виджет с другим;
- переносить целые группы связанных элементов;
- менять масштаб каждого блока;
- сохранять персональную раскладку;
- добавлять и удалять виджеты, сохраняя их индивидуальные настройки для повторного использования.

### Управление в редакторе

| Действие | Как работает |
| --- | --- |
| Перемещение | зажать ЛКМ по виджету |
| Масштабирование | `Ctrl` + колесо мыши |
| Тонкая регулировка масштаба | `Ctrl` + `Shift` + колесо |
| Перетаскивание группы | удерживать `Alt` при начале перетаскивания |
| Привязка к якорю | поднести виджет к якорной точке |
| Добавить виджет | нажать `+` или его строку в боковой панели |
| Достать виджет из-под панели | перетащить его добавленную строку из списка |
| Скрыть/показать библиотеку | `Tab` в редакторе |
| Настройки виджета | ПКМ по виджету или его добавленной строке в библиотеке; `Esc` — обратно |
| Удалить виджет | нажать `-` в панели, крестик на виджете или `Delete` для выбранного |
| Сохранение позиции | автоматически после отпускания |

### Основная раскладка

Основная раскладка — постоянная база HUD. Её нельзя удалить, переименовать или привязать к локации; состав виджетов, позиции и масштаб редактируются как обычно. При обновлении текущая раскладка сохраняется.

Нажмите название раскладки в заголовке боковой панели, чтобы переключиться или создать новую через `+ New layout`. Кнопка `...` рядом с названием дополнительной раскладки открывает её имя, `Location visibility` и удаление. Дополнительная раскладка действует только в выбранных локациях; пустой список делает её неактивной в игре, но не мешает редактированию.

Основная и подходящие дополнительные раскладки объединяются. Каждый виджет существует в единственном экземпляре: раскладка локации меняет его позицию, масштаб и привязки. По выходе из локации возвращается основное размещение. Если подходят несколько дополнительных раскладок, размещение берётся из последней созданной подходящей раскладки, содержащей этот виджет.

При автоматической смене раскладки после телепорта появление и исчезновение виджетов занимает 0,5 секунды. Виджет, который остаётся видимым, плавно меняет позицию и масштаб за 0,2 секунды. Повторный переход продолжает анимацию с текущего положения и прозрачности. При смене выбранной раскладки редактор сразу показывает её размещение; в конфиг сохраняются конечные координаты.

В меню виджета по ПКМ есть `Location visibility` (виден только в выбранных местах) и `Location hidden` (скрыт только в выбранных местах). Режимы взаимоисключающие: выбор в одном очищает другой. Оба списка пустые — без ограничения локаций. Эти фильтры действуют во всех раскладках и не создают копий виджета.

Выбор локаций поддерживает поиск по названию и серверному ID, группы локаций, `+ Current` и `Clear`. Введите точный ID и нажмите Enter, чтобы добавить отсутствующую локацию; суффикс `*` задаёт группу по префиксу ID. Названия показываются для удобства, совпадение проверяется по ID, полученному от DW. Пока локация неизвестна, разрешающий список скрывает виджет, запрещающий — оставляет его видимым.

Локация берётся из серверного `statisticinfo.gameLocation`. На JOIN мод сразу отправляет DW handshake; после Respawn без нового JOIN выполняет один объединённый запрос обновления, если новая локация ещё не поступила. При получении пакета раскладка применяется на первом следующем кадре.

В игре виджеты появляются, когда для них доступны данные и выполняются условия видимости. В редакторе выбранная раскладка показывается независимо от текущей локации и фильтров, включая preview без данных сервера.

Включение/выключение виджетов убрано из обычных настроек: состав раскладки меняется только в редакторе. Настройки конкретного виджета открываются по ПКМ на нём или его добавленной строке в библиотеке. У всех виджетов доступен масштаб; параметры содержимого показываются только для выбранного виджета. `Esc`, кнопка `< Back` или клик вне меню возвращают в редактор, изменения сохраняются автоматически. Общие настройки оформления остаются в меню `O`. Из раздела `Widget` можно перейти в редактор через `Edit Main Layout`.

Числовые настройки меняются перетаскиванием самого числа влево/вправо. `Shift` уменьшает чувствительность в 10 раз. На изменения проигрывается короткий тик `scroll`, с общим ограничением 40 звуков в секунду.

Звуки FrogHelper сопровождают открытие и закрытие меню, кнопки, переключатели, наведение, прокрутку и работу с виджетами. У появления босса, личных сообщений, находок и готовности умений свои сигналы. Громкость всех звуков мода регулируется ползунком **UI** в настройках звука Minecraft; общая громкость тоже действует. Звук подсказок алхимии по-прежнему можно отключить в её настройках.

Во время перетаскивания библиотека скрывается, освобождая весь экран для позиционирования. Внизу панели показывается только счётчик добавленных виджетов.

При добавлении виджет растёт от нулевого размера до своего масштаба за 0,2 секунды; при удалении уменьшается до нуля за 0,2 секунды. Анимация идёт от центра, вместе с фоном, текстом и иконками. Состав раскладки изменяется сразу, сохранённый масштаб остаётся прежним.

Добавление, удаление и изменение раскладки сохраняются автоматически. Удалённый виджет сохраняет настройки и последнее положение; при повторном добавлении он восстанавливается. Пустая раскладка также сохраняется и не заполняется заново после перезапуска.

## HUD и виджеты

Ниже перечислены основные HUD-элементы, которые мод умеет показывать игроку.

### Боссы и бой

| Виджет | Что показывает |
| --- | --- |
| **Boss Timers** | список боссов с таймерами возрождения |
| **Boss Bar** | кастомный блок с полосой босса |
| **Boss Damage** | ваш текущий или последний урон по боссу |
| **Ability Cooldowns** | откаты способностей |
| **Wand Cooldowns** | откаты палок / связанных умений |
| **Combo Progress** | текущий прогресс комбо |
| **Blocks/s** | скорость ломания блоков |
| **Estimated TPS** | клиентская оценка TPS сервера |

### Boss Timers

Список боссов с обратным отсчётом до возрождения. Дополнительно:

- уже возродившийся босс какое-то время продолжает висеть с таймером «в минусе» и подсвечивается цветом Hard Accent (см. [Тему](#тема-и-внешний-вид)), а не пропадает мгновенно;
- диапазон уровней (`Min level` / `Max level`) настраивается; верхняя граница автоматически расширяется, когда сервер вводит боссов выше текущего потолка;
- источник данных выбирается между протоколом и миром (`Source mode`), плюс есть настройки иконок, имён, уровней и выравнивания.

### Wand Cooldowns

Таймеры посохов приходят из серверного протокола. Для Посоха Ветра, Посоха Вихря и локального названия `Величие гарпии` использование дополнительно отслеживается по предмету в руке, чтобы откат появлялся без ожидания следующего пакета.

Тумблер `Numeric Cooldown` заменяет полосу прогресса числом. В последнюю секунду оставшееся время показывается с десятыми долями секунды.

### Estimated TPS

Виджет показывает:

- текущий `TPS`;
- `1% low`;
- `0.1% low`.

Для него есть отдельный флаг `Enable Estimated TPS Monitor`. Если он выключен, мод вообще не собирает сэмплы и не тратит ресурсы на расчёт.

### Прогресс и активные эффекты

| Виджет | Что показывает |
| --- | --- |
| **Level Progress** | прогресс уровня |
| **Boosters** | активные бустеры и их длительность |
| **Potions** | откат до следующего доступного приёма зелья и период готовности после него |
| **Active Runes** | активные руны |
| **Active Pets** | активных питомцев |
| **Miners** | статус майнеров |
| **Seller Cooldowns** | откаты продавцов и похожих систем |
| **Visibility Status** | текущий режим видимости игроков / клана / питомцев |

### Рецепты и полезные панели

| Виджет | Что делает |
| --- | --- |
| **Craft Recipe** | показывает рецепт крафта |
| **Dungeon / Siege Map** | отображает карту данжа / осады |
| **Fishing Nibbles** | показывает информацию по клёву |
| **Fishing Quests** | показывает рыболовные задания и их прогресс из серверных пакетов, включая часовые задания; фильтр по измерению |
| **Entity Inspect** | блок с информацией о сущности под прицелом |

### Дополнительно по виджетам

- большинство виджетов можно свободно двигать и масштабировать;
- layout сохраняется между запусками;
- виджеты можно сцеплять и перемещать группами;
- для части виджетов есть compact-режим;
- для тяжёлых функций добавлены предупреждения о влиянии на производительность.

### UnClutter

Тумблер `UnClutter (hide widget titles)` (категория `Widget`, включён по умолчанию) убирает подписи-названия внутри виджетов — остаются только сами данные (например, у `Active Runes` пропадает заголовок, остаются строки рун). Скрытие действует и в игре, и в редакторе, а фон и акцентная линия виджета остаются на месте. Виджеты, где верхняя строка сама по себе является данными (например `Level Progress`, `Combo Progress`), тумблер не затрагивает.

## Discord RPC

В FrogHelper встроен собственный Discord IPC-коннектор без внешних RPC-библиотек. При смене локации или подсервера обновление ставится в очередь на ближайшем клиентском тике, без ожидания интервала обновления прогресса. Работа с Discord остаётся асинхронной.

### Что показывает RPC

Discord Rich Presence умеет отображать:

- текущий сервер и зеркало;
- локацию;
- уровень;
- комбо;
- активный game event;
- elapsed time;
- режим активности по типу локации.

### Режимы активности

RPC автоматически подбирает статус и иконку в зависимости от ситуации:

| Режим | Что обычно означает |
| --- | --- |
| `froghelper` | нейтральный fallback |
| `hub` | хаб / спавн / лобби |
| `mine` | шахта |
| `dungeon` | данж |
| `siege` | осада |
| `boss` | босс |
| `fishing` | рыбалка |
| `death` | смерть / ожидание респавна |
| `event` | маленькая иконка активного ивента |

### Privacy Mode

Есть отдельный `Privacy mode`.

В нём RPC почти пустой:

- базовая иконка `froghelper`;
- строка `FrogHelper`;
- без сервера, локации, событий и прочих деталей.

### Настройки Discord

Во вкладке `Discord` можно управлять:

- `Enable auto RPC`
- `Privacy mode`
- `Show elapsed time`
- `Show server`
- `Show mirror`
- `Show location`
- `Show level`
- `Show combo`
- `Show game event`

## Чат и общение

### Вкладки чата

Сообщения автоматически раскладываются по вкладкам:

- общий чат;
- приваты;
- отдельные категории по префиксам и типам сообщений.

### Метки времени

Каждое сообщение можно снабжать временем в формате `HH:mm:ss`, чтобы было легче понимать, когда именно произошло событие.

### Tone Down Chat

Опция делает чат визуально спокойнее:

- убирает часть визуального шума;
- уменьшает агрессивную декоративность;
- делает переписку аккуратнее и легче читаемой.

### Копирование сообщений

ПКМ по строке чата копирует тело сообщения без timestamp, канального префикса, ранга и ника отправителя. Поведение включается тумблером `Copy chat by RMB`.

При включённом `Full Message Copy` копируется полная отображаемая строка: timestamp, канал, ранг, ник и текст. Внутренние служебные символы FrogHelper в буфер обмена не попадают.

После копирования можно получить pop-up уведомление.

### Auto Thanks

Если кто-то активировал глобальный бустер, мод может автоматически отправить `thx`.

### Приваты и pop-up уведомления

На входящий приват можно получить отдельный pop-up:

- с превью текста;
- без необходимости постоянно держать чат открытым.

### Обмен таймерами боссов

Команда `/fhshare <ник>` отправляет ваши локальные таймеры боссов другому игроку с FrogHelper.

### Пользователи FrogHelper и Socials

После входа на DW FrogHelper автоматически авторизуется на backend и получает список пользователей мода по WebSocket. Социалка работает всегда; отдельного тумблера `Socials` нет. Старые выключенные значения `socialsEnabled` и `modUserMesh` в конфигурации игнорируются.

Клавиша `C` открывает список игроков с модом онлайн. Значок жабки в TAB, чате и над игроком служит визуальным оформлением; настройка `FrogHelper Badge On Nametags` управляет отображением над игроком.

Backend создаёт Discord embed при входе и обновляет его при переходах и выходе. Адрес webhook настраивается на сервере. Смена локации обходит обычные интервалы обновления метаданных и embed. Лимит отправки в API (не чаще одного кадра в секунду), последовательная доставка, повторы после ошибок и ограничения Discord сохраняются.

## Quick Access

Quick Access — это быстрое секционное меню действий, открываемое удержанием клавиши.

### Что это даёт

- быстрый доступ к частым командам;
- меньше ручного ввода;
- удобный выбор действий буквально за одно удержание клавиши.

### Как это работает

1. зажимаете `R`;
2. на экране появляется меню с секциями и слотами;
3. наводитесь на нужное действие;
4. отпускаете `R`;
5. команда выполняется автоматически.

### Стандартные секции

По умолчанию есть заготовки вроде:

- `Common`
- `Travel`
- `Player`

### Подстановка `{player}`

Некоторые команды могут автоматически подставлять ник игрока под прицелом.

Это полезно для:

- статистики;
- трейда;
- быстрых действий по выбранной цели.

### Встроенный редактор Quick Access

Через настройки можно открыть отдельный редактор и:

- создавать секции;
- добавлять и удалять слоты;
- менять названия;
- менять команду;
- менять иконку предмета;
- задавать `CustomModelData`;
- перетаскивать элементы между секциями.

## Оверлеи и подсветка

### Fishing

Рыболовный блок умеет:

- показывать рыболовные метки по серверным пакетам `BUBBLE`, `LAVA`, `DUST` и прежним вариантам пузырьков; метки работают и при минимальном количестве частиц;
- выводить виджет по клёву;
- использовать данные протокола по fishing spots;
- автоматически дёргать удочку при срабатывании, если включён Auto Fish.

### Алхимия

Подсвечивает ингредиенты алхимии прямо в мире.

### Данжи и осады

Поддерживаются:

- карта данжа / осады;
- подсветка важных декоративных элементов и ориентиров.

### Полосы HP игроков

Мод умеет рисовать полосы здоровья над игроками:

- с настройкой прозрачности;
- с вертикальным смещением;

Насколько резко происходит смена цвета, задаётся ползунком `Accent strength %`: при высоком значении переход читается чётко, а не еле заметным затуханием.

### Useful Items Highlight

Подсветка полезных объектов и предметов помогает быстрее замечать важные точки в мире.

## Автоматизация и утилиты

### Auto Messages

Система авто-сообщений позволяет настроить слоты с сообщениями, которые будут отправляться по таймеру.

Для каждого слота задаются:

- текст;
- активность;
- задержка в секундах.

### Clicker

Позволяет включить авто-нажатие с заданной скоростью.

Настройки:

- CPS;
- режим атаки;
- режим использования предмета вместо атаки.

### Auto Fish

Полуавтоматическая рыбалка:

- отслеживает состояние поплавка;
- ждёт нужное количество тиков;
- автоматически делает нужное действие.

### Boss Respawn Messages

Мод умеет локально уведомлять о важных этапах босса:

- сообщение перед респавном;
- сообщение о спавне;
- сообщение о проклятии;
- сообщение о низком HP.

В отдельном разделе **Low HP Message** есть конструктор с цветным предпросмотром.
Подсервер, имя, уровень, проклятие, HP, процент HP и подпись стадии можно скрывать
независимо друг от друга. Цвет каждого элемента задаётся кодом `&0`–`&f`
(также принимается `§0`–`§f`). Настройки общие для локального и кланового сообщения.
Пример: `[PE1.2] Бессмертный Легион [130] — 125❤ (20%) [Стадия 2/4]`.
При скрытии всех элементов сообщение не отправляется.

Встроенная система всплывающих уведомлений сообщает о событиях вроде:

- входящего привата;
- появления босса;
- готовности способности;
- готовности wand-умения;
- готовности продавца;
- возвращения майнера;
- окончания отката набора рун;
- окончания зелья;
- окончания бустера;
- копирования чата.

Дополнительно настраиваются:

- число одновременно видимых pop-ups;
- длительность показа;
- скорость появления;
- скорость исчезновения.

## Профайлер

В FrogHelper встроен собственный семплирующий профайлер. Он нужен, чтобы **точно** понять, какая часть мода нагружает клиент, а не гадать — именно через него в несколько итераций оптимизировалась подсветка мира. Это в первую очередь инструмент для диагностики просадок FPS и фризов.

### Ключевые свойства

- **Выключен по умолчанию**. Флаг **Render → Visual → Debug** включает только минимальный фоновый сбор в памяти, в том числе в главном меню. Подробные замеры и запись на диск запускаются вручную через `/fhprof start`. При выключенном Debug и отсутствии ручной сессии замеры и периодические снимки не собираются.
- Полностью **клиентский и локальный**: ничего не отправляется на сервер, отчёты сохраняются в файл на вашем диске.
- Замеряет именованные участки кода (секции) и счётчики событий по всему моду: рендер, HUD, отдельные виджеты, тики, обработку протокола и т. д. Применение раскладки (`hud/layout/apply`), анимации (`hud/animation/`) и боковая панель (`ui/widgetSidebar/render`) имеют отдельные замеры; добавление и удаление виджетов отмечаются в журнале событий.
- Фоновый сбор остаётся минимальным: снимки памяти, FPS и доступных счётчиков примерно раз в 10 секунд, ограниченная история событий подключения. Debug не создаёт файлы и не запускает JFR; накопленные данные можно сохранить командой `/fhprof dump`. Автоматический сбор не перебирает сущности и чанки, не строит гистограмму кучи. Подробные типы объектов мира доступны в ручном отчёте.

### Visuals: экран, контур блока и цвета мира

В разделе **Visuals** доступны независимые настройки:

- **Aspect ratio**: Off, 4:3, 5:4, 3:2, 16:10, 16:9, 21:9, 1:1 и Custom.
  Custom задаётся шириной/высотой, допустимое итоговое соотношение — от 1:4 до 4:1.
  Это изменение перспективы мира, а не разрешения окна или размера HUD.
  **Stretch hand too** позволяет применять его также к руке.
- **Custom block outline**: цвет и толщина 1–8 px. Используется точный контур
  выбранного блока, включая неполные формы, без заливки, свечения и сквозного рендера.
- **Custom sky color / Custom fog color**: независимые переключатели и RGB-палитры
  с вводом HEX. Дальность тумана и его поведение в воде/лаве/рыхлом снеге сохраняются.

Все три возможности по умолчанию выключены; выключение возвращает ванильный рендер.
Настройки применяются сразу и сохраняются в froghelper.json, без EvoPlus/Kotlin.

### Лёгкий HUD для слабых компьютеров

В настройках **Widget → Core → Lightweight HUD (no blur / item icons)** можно
отключить блюр, сглаженные панели и модели предметов во всех виджетах FrogHelper.
Текст, таймеры, действия виджетов и их расположение сохраняются. Эта настройка не
меняет обычный инвентарь Minecraft, модели в мире и настройки других модов.
По умолчанию режим выключен; включение не требует перезапуска игры.

Имена и объединённые списки таймеров боссов кешируются до изменения данных;
строки отсчёта обновляются при изменении отображаемой секунды. Смена сроков,
имён и иконок, истечение таймера и смена настроек учитываются при обновлении.
Проверка размеров закреплённых виджетов во время игры выполняется до 10 раз в секунду;
редактор продолжает пересчитывать расположение на каждом кадре.

### Команда `/fhprof`

| Команда | Что делает |
| --- | --- |
| `/fhprof status` | состояние, режим (`debug-memory`, `manual`, `debug-memory+manual`), число секций и счётчиков, длительность и путь записи |
| `/fhprof start` | сбрасывает статистику, включает подробные замеры и запись на диск; история фоновых снимков сохраняется |
| `/fhprof stop` | останавливает подробные замеры и запись на диск; при включённом Debug минимальный сбор в памяти продолжается |
| `/fhprof reset` | очищает накопленную статистику |
| `/fhprof report [prefix]` | выводит топ секций и счётчиков прямо в чат |
| `/fhprof dump [prefix]` | сохраняет Markdown-отчёт без принудительной гистограммы кучи |
| `/fhprof dump-full [prefix]` | дополнительно собирает гистограмму классов JVM; может временно заморозить игру |

Без аргументов `/fhprof` эквивалентен `/fhprof status`.

Типичный сценарий: `/fhprof start` → поиграть в проблемной ситуации 20–60 секунд → `/fhprof dump` → открыть сохранённый файл.

### Фильтр по префиксу

Секции именуются с префиксами: `render/`, `hud/`, `widget/`, `tick/`, `ui/`, `world/`, `protocol/`. Необязательный `prefix` в `report` и `dump` оставляет только совпадающие секции — удобно сфокусироваться на подсистеме:

```text
/fhprof report render/
/fhprof dump render/UsefulWorldHighlightRenderHook
```

### Куда сохраняется отчёт

`/fhprof dump` пишет файл в папку `froghelper-profiler` внутри директории игры:

```text
<game>/froghelper-profiler/fhprof-<дата-время>.md
```

При использовании фильтра имя файла содержит префикс: `fhprof-<prefix>-<дата-время>.md`. Путь к сохранённому файлу выводится в чат.

`/fhprof start` запускает сохранение контрольных копий для восстановления после краша
и создаёт папку `froghelper-profiler/fhprof-live-<дата-время>-<pid>-<номер>`.
`/fhprof stop` сохраняет финальное состояние ручной сессии независимо от Debug.
Если сейчас идёт автоматический 15-секундный профиль, он заканчивается по своему таймеру.
Выключение Debug останавливает только фоновый сбор в памяти; явно запущенная ручная сессия продолжается до `/fhprof stop`.
Без Debug, ручной сессии и автоматического события FPS диагностика не собирается. В папке ручной сессии находятся:

- `environment.json` — версия Java, параметры JVM и установленные моды;
- `events.jsonl` — события переходов, снимки клиента и память JVM/системы; фоновая запись примерно раз в секунду продолжается при зависшем клиенте;
- `report.md` — автоматически обновляемый Markdown-отчёт примерно раз в 5 секунд;
- `profile.jfr` — JFR последних двух минут с ограничением хранения 32 MiB, обновляемая примерно раз в 5 секунд.

JFR запускается самим модом для ручной сессии `/fhprof start` либо автоматического профиля при низком FPS, с настройками `default`; отдельный `-XX:StartFlightRecording` для этой записи не нужен.
Чтобы включить также учёт нативной памяти JVM в JFR, можно добавить
`-XX:NativeMemoryTracking=summary` при запуске Java. Уже запущенные внешние записи JFR мод не останавливает.

Готовые `report.md` и `profile.jfr` заменяются только после полной записи новой копии.
Сохранённые данные остаются даже при принудительном завершении JVM без shutdown hook;
последние несохранённые секунды могут потеряться. Последняя строка журнала может быть
оборвана крашем — при чтении учитываются только законченные JSON-строки.
Журнал ограничен двумя файлами примерно по 8 MiB: `events.jsonl` и `events.previous.jsonl`.
При остановке профайлера сохраняется финальная копия. Путь и ошибки автосохранения
можно посмотреть через `/fhprof status`. `/fhprof dump` сохраняет отдельный отчёт без тяжёлой гистограммы классов.
Гистограмма доступна через `/fhprof dump-full`: JVM останавливает потоки для её сбора,
поэтому такую команду лучше запускать вне боя. Автоматические контрольные копии гистограмму не собирают.

### Автоматические отчёты об ошибках

При FPS ниже **15** в активном окне во время игры на DW мод автоматически собирает
**15 секунд** подробного профиля и JFR. Debug включать не требуется. Запись останавливается
таймером вне игрового потока, даже если клиент завис. Ручная сессия `/fhprof start`
продолжает работать: автоматический отчёт содержит отдельное окно замеров из той же записи.
Новый профиль возможен не чаще раза в **10 минут** и после восстановления до 20 FPS
как минимум на 5 секунд; постоянная просадка не создаёт бесконечные отчёты.

При запуске проверяется последний `crash-reports/crash-*.txt` или `hs_err_pid*.log`.
Нативные логи из рабочей/временной директории проверяются на принадлежность Minecraft
и этой игровой директории, если она указана. Отчёт отправляется после автоматической
авторизации на DW. Уже принятый краш повторно не отправляется; исходный лог сохраняется.
Принудительное завершение процесса не всегда создаёт краш-лог: отсутствующий файл
мод восстановить не может. Общий `latest.log` с чатом не отправляется.

ZIP с отчётом передаётся по HTTPS на собственный backend с действующей сессией;
backend отправляет embed и вложение через серверную переменную `DISCORD_ERROR_WEBHOOK_URL`.
Адрес webhook отсутствует в клиенте. Токены, пароли и webhook-адреса скрываются в
текстах; из отправляемого JFR исключаются события с аргументами запуска и переменными среды.
Упаковка и сеть работают вне игрового потока. После успешной упаковки временная
автоматическая запись удаляется; файлы ручной сессии сохраняются.

При потере связи архив остаётся в `<game>/froghelper-profiler/diagnostics` и отправляется
повторно с паузой. Очередь ограничена **8 архивами / 32 MiB**, архив — **8 MiB**.
Если JFR не помещается, отправляется текстовый отчёт с объяснением. Когда очередь полна,
новые автоматические записи не запускаются. В обычной игре постоянной записи на диск нет:
Debug по-прежнему хранит только минимальные снимки в памяти.

### Что внутри отчёта

Markdown-отчёт удобно читать/прикладывать при разборе проблем. В нём:

- **Session Context** — версии FrogHelper / Minecraft / Fabric Loader, окружение, сервер, экран, измерение, ник, FPS, размер окна;
- **Summary** — главные горячие точки (по суммарному времени, по self-времени и самый большой одиночный спайк);
- таблицы **Top Sections** — по суммарному времени, по self-времени и по максимальным спайкам;
- **Call Tree** — дерево вложенных замеров;
- **Recent / Worst Samples** — история недавних и худших кадров/тиков;
- **Top Counters** — счётчики событий;
- **Legend** — расшифровка метрик.

### Метрики

| Метрика | Смысл |
| --- | --- |
| `calls` | сколько раз секция была измерена |
| `total` | суммарное время в секции |
| `self` | время в секции без вложенных измеренных участков |
| `avg` | среднее время на вызов |
| `max` | худший одиночный спайк |
| `share` | доля секции от всего измеренного времени |
| счётчики (`events` / `total`) | число событий и накопленные «единицы работы» — это не время, а количество (например, сколько чанков просканировано) |

## Команды мода

### `/fhshare <ник>`

Отправляет ваши локальные таймеры боссов указанному игроку.
